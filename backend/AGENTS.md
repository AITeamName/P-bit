# backend — AI working rules

Spring Boot API server. The extension and the web share the same API and the same DB.
The root `AGENTS.md` also applies. Inside this folder, this file wins on conflict.
Workflow rules (branches, commits, PRs, approvals) live only in the root `AGENTS.md`. This file holds tech rules only.

Reference documents are written in Korean. Section titles below keep the Korean originals so you can search for them as written.

## 1. Stack and commands

- Java 17, Spring Boot 4.0.x, Gradle (`backend/build.gradle`)
- PostgreSQL 16, Flyway, Spring Data JPA (Hibernate)
- Spring Security, jjwt, springdoc-openapi 3.0.x, Lombok

Spring Boot 4 — do not copy Boot 3 examples as they are.

- Jackson 3.x: `tools.jackson.databind.ObjectMapper` (not `com.fasterxml`)
- Web tests: `org.springframework.boot.webmvc.test.autoconfigure.WebMvcTest`
- springdoc 3.0.x (2.x is for Boot 3)

Pre-commit routine (run in `backend/`; same command as the CI `backend` job)

```bash
docker compose up -d          # DB (from the repository root) — needed by @SpringBootTest
./gradlew build               # compile + test
```

## 2. Structure

```
com.pbit.api
├─ global/            shared by several features
│   ├─ config/         Security, CORS, OpenAPI, Clock, and other config
│   ├─ auth/           JWT issue/verify, auth filter, refresh cookie
│   ├─ error/          ErrorCode, BusinessException, ErrorResponse, GlobalExceptionHandler
│   └─ logging/        RequestIdFilter
├─ domain/{feature}/  per feature (auth · user · term · session · event · record · dashboard)
│   ├─ controller/  service/  repository/  entity/
│   └─ dto/            request/ · response/
└─ infra/ai/          FastAPI calls (AiClient, AI DTOs) — create here when needed
```

- New features follow the same shape. Do not create empty folders.
- Put code in `global/` only when several features use it. Code used by one feature stays in that feature.
- To use another feature's data, call that feature's Service. Do not use another feature's Repository directly.

## 3. Rules

### Layers

- Call direction: Controller → Service → Repository. No reverse calls.
- Controller: request validation (`@Valid`) and the response only. No business logic.
- Service: business logic and transactions. Reads use `@Transactional(readOnly = true)`.
- Never return an entity as an API response. Always map to a response DTO.
- Call FastAPI outside any DB transaction, then save the result in a short transaction.

### DTOs

- Use `record`. Name them `{Action}Request` / `{Action}Response`.
- Validate with Bean Validation and put the user-facing text in `message`. It becomes `fieldErrors[].reason` in the error response.
- Map entity → response with a static `from(entity)` on the response DTO.
- JSON fields are camelCase. Convert to FastAPI's snake_case and lowercase enums only in the `infra/ai` DTOs (`docs/dev/specs/interfaces.md` > 7장).

### Errors

- Throw only `new BusinessException(ErrorCode.XXX)`. Do not create new exception classes.
- If a code is missing, add it to the error code table in the API specification first, then to `ErrorCode`.
- The response shape is fixed: `ErrorResponse` (code, userMessage, retryable, requestId, fieldErrors, fallback). There is no `message` field.
- Log the cause of unexpected exceptions; never put it in the response.

### JWT and auth

| Item | Rule |
| --- | --- |
| Access token | JWT, HS256, 30 min, `Authorization: Bearer` |
| Access claims | `sub` = userId and `role` only. No personal data such as email or nickname |
| Refresh token | Opaque random string, 14 days. Store only its SHA-256 hash in the DB |
| Rotation, reuse | Issue a new refresh token on every refresh and revoke the old one (`revoked_at`). A revoked token gets `REFRESH_TOKEN_INVALID` |
| Web delivery | Cookie `refresh_token` (`HttpOnly`, `SameSite=Lax`, path `/api/v1/auth`). Only the `local` profile turns `Secure` off |
| Extension delivery | In the request/response body (no cookie) |
| Device | `refresh_tokens.client_type` = `WEB` · `EXTENSION`. Logout revokes the current device only |
| Errors | Expired `TOKEN_EXPIRED`, forged/missing `TOKEN_INVALID`, refresh problems `REFRESH_TOKEN_INVALID` |
| Secrets | `JWT_SECRET` and others come from environment variables only. No defaults in code or config files |

- List APIs that allow anonymous access explicitly in `SecurityConfig`.
- Always check the owner (`user_id`) of user data. If it differs, `FORBIDDEN`.
- Production also keeps `SameSite=Lax`. This assumes the web and the API share a parent domain (placement is agreed with the cloud part, `docs/dev/specs/architecture.md` > 2.5).

### DB

| Target | DB | Java |
| --- | --- | --- |
| Client-facing IDs | `UUID` | `UUID`, generated by Java (`@Id @GeneratedValue`) |
| Internal and log table IDs | `BIGINT IDENTITY` | `Long`, `GenerationType.IDENTITY` |
| Enums | `VARCHAR` + `CHECK` (no PG ENUM) | enum + `@Enumerated(EnumType.STRING)` |
| Time | `TIMESTAMPTZ`, UTC | `Instant`. No `LocalDateTime`. Convert to `Asia/Seoul` only for display and aggregation |
| Raw judgment | `JSONB` | `@JdbcTypeCode(SqlTypes.JSON)` |

- Names: tables and columns `snake_case`, tables plural. Indexes `idx_{table-abbr}_{purpose}`, unique `uq_{table}_{column}`. Entities singular PascalCase.
- Store raw judgments exactly as FastAPI returns them; keep aggregated values in separate columns. Judgment logs must include `rubric_version` · `domain` · `language`.
- Soft delete only for `users` (`deleted_at` + masking personal data).
- Never change `before_after_records.result_snapshot` after saving (no re-scoring).
- Get the current time from the injected `Clock` (`global/config/ClockConfig`).

### Schema changes (Flyway)

- Change the schema only through Flyway: `src/main/resources/db/migration`
- Never edit an applied `V*.sql`. Add a new file `V{next}__{description}.sql`.
- Keep `spring.jpa.hibernate.ddl-auto` at `validate`.
- When a table or column changes, update `docs/dev/specs/erd.md` too.

## 4. Tests

- Web layer (controllers, error responses, security): `@WebMvcTest`. Runs without a DB.
- `@SpringBootTest` and repository tests need PostgreSQL (`docker compose up -d`).
- Test method names describe condition and result in Korean (e.g., `중복_이메일이면_409를_응답한다`).

## 5. Prohibitions

- Do not read or commit `.env`. Add only the key name to `backend/.env.example`.
- Never log `prompt_text` (the user's raw prompt). Store it in the DB only.
- Do not add APIs or response fields that are not in the specification. If the implementation must differ, change the specification first.
