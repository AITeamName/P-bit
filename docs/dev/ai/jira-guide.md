# Jira 이슈 작성 가이드

> 담당: AI 협업 도구 · 최종 수정: 2026-11-22
> 출처: Jira 이슈 작성 양식 (Notion)

Jira 이슈를 쓸 때 아래 양식을 복사해서 설명란에 붙여 넣는다. 안 쓰는 항목은 지워도 된다. 개발이든 아니든 양식을 기준으로 쓴다.

- 사람이 Jira 화면에서 직접 쓸 때와 AI가 쓸 때(`docs/dev/ai/prompts/20-issue-write.md`) 같은 양식을 쓴다.
- 각 양식 위의 HTML 주석은 AI 작성 안내다. 이슈에 붙여 넣을 때는 지운다.
- 완료를 체크할 목록(작업 내용, 완료 조건, 할 일, 후속 조치)은 체크박스(`- [ ]`)로 쓴다. 그 밖의 목록은 글머리(`-`)로 쓴다.
    - Jira 설명란은 마크다운이 아니라 ADF라는 형식이라, `- [ ]`를 그대로 붙여 넣거나 MCP에 `format: markdown`으로 보내면 체크박스가 아니라 `[ ]` 글자로 남는다.
    - AI가 등록할 때(Claude Code): 초안을 ADF로 바꿔 체크박스를 Jira 체크리스트로 등록한다 (§9).
    - 사람이 Jira 화면에서 쓸 때: 편집기에서 `[]` 다음 스페이스를 입력하면 체크리스트 항목이 생긴다.
- 하위 작업(Subtask)은 가능하면 만들지 않는다 (§4).

---

## 1. 제목 규칙

```
[파트] 동사 + 대상

예) [BE] 회원가입 API 구현
    [FE] 사이드바 진단 화면 퍼블리싱
    [LLM] 판정 프롬프트 v2 튜닝
    [DOC] 백엔드 기술 기획서 v1.1 공유
```

| 파트 태그 | 대상 | 브랜치·커밋 scope |
| --- | --- | --- |
| `BE` | 백엔드 | `be` |
| `FE` | 프론트 (웹 · 익스텐션 공통) | `web` · `ext` · `fe` 중 바꾸는 폴더 기준 |
| `EXT` | 크롬 익스텐션만 바꾸는 작업 | `ext` |
| `LLM` | 생성형 AI / FastAPI, AI 협업 도구 | `llm` · `ai` |
| `DE` | 디자인 | `de` |
| `INFRA` | 클라우드 · 배포 · CI | `infra` |
| `DOC` | 문서 · 기획 | 바꾸는 문서 위치 기준 (`CONTRIBUTING.md` > `1.3 Scope 정의`) |
| `MTG` | 회의 · 협의 | 없음 |

- PR 제목에서는 파트 태그를 빼고 scope로 바꾼다 (`.github/pull_request_template.md` 안내 주석).

## 2. 필드 규칙 (설명란 밖)

| 필드 | 규칙 |
| --- | --- |
| 담당자 | 1명 |
| 라벨 | 파트명(`BE` `FE` …) + 기능(`인증` `온보딩` `진단` `점검` `연습` `대시보드`) |
| 에픽 | 큰 기능 묶음(세팅 / 인증 / 온보딩 / 진단 / 점검 / 연습 / 대시보드 / 배포). 작업은 에픽 아래 Story·Task로 만들고, 하위 작업(Subtask)은 가능하면 만들지 않는다 (§4) |
| 크기 | 하루 안에 못 끝내면 나눈다 |
| 브랜치 | `{type}/KAN-{번호}-{설명}` → 예) `feat/KAN-12-signup-api` (`CONTRIBUTING.md` > `1.2 브랜치 네이밍`) |
| 커밋·PR | 커밋: `feat(be): 회원가입 API 구현 (KAN-12)` / PR: `[KAN-12] feat(be): 회원가입 API 구현` |

## 3. 개발 (Story / Task)

```markdown
<!--
[AI 작성 안내 — Jira MCP·커넥터로 등록할 때]
이슈 유형: Story 또는 Task
제목 형식: [파트] 동사 + 대상
  예) [BE] 회원가입 API 구현
  예) [LLM] 형식 요소 판정 엔드포인트 구현
  예) [FE] 사이드바 진단 화면 퍼블리싱
각 섹션 작성 기준:
- "목적": 누가 무엇을 할 수 있도록 무엇을 구현하는지 1~2줄.
  "~를 구현한다"가 아니라 "~이 가능하도록 ~를 구현한다".
- "작업 내용": 이번 이슈 범위에서 끝내야 할 항목만.
  각 항목은 완료 여부를 따로 판정할 수 있는 단위로 쓴다.
- "완료 조건": 동작 확인 방법, 테스트·Swagger 반영, PR 머지를 포함한다.
- "연관 파트": 다른 파트에 영향을 주거나 받는 작업이면 반드시 쓴다.
  해당 파트 담당자를 Jira 워처(Watcher)로 추가한다.
- 코드·명령어·파일 경로·함수명은 `코드블록`으로 감싼다.
- 크기가 하루를 넘으면 나눈다.
등록 시 필드:
  issuetype: Story 또는 Task
  summary:   [파트] 동사 + 대상
  labels:    [파트명, 기능명]
  assignee:  담당자
-->
```

```markdown
## 목적
왜 하는지 1~2줄

## 작업 내용
- [ ] 
- [ ] 

## 완료 조건 (DoD)
- [ ] 동작 확인 방법
- [ ] 테스트 / Swagger 반영
- [ ] PR 머지

## 참고
- 기획서: (Notion 링크 + 섹션 번호)
- 화면: (Figma 프레임 링크)
- 설계 문서: (저장소 문서 > 섹션)

## 의존성
- 선행: KAN-00
- 협의 필요: 파트

## 연관 파트
- 영향 주는 파트: (이 작업에 필요한 것을 주는 쪽) 예) LLM — 판정 응답 형식
- 영향 받는 파트: (이 작업 결과를 쓰는 쪽) 예) FE — 응답 필드 변경
- 공유 필요 사항: (API · DTO · 프롬프트 · 화면 변경 등)
```

> **연관 파트**: 다른 파트에 영향을 주거나 받는 작업이면 반드시 쓴다. 해당 파트 담당자를 Jira 워처로 추가한다. 없으면 `없음`.

**작성 예시 — [BE]**

- 제목: `[BE] 회원가입 API 구현`
- 목적: 웹 자체 회원가입 기능을 제공해 사용자가 서비스에 직접 가입할 수 있도록 한다 (WEB-JOIN-01/02)
- 작업 내용
    - [ ] `POST /api/v1/auth/signup` 구현
    - [ ] 이메일·닉네임 중복 확인 API
    - [ ] 약관 동의 저장
- 완료 조건
    - [ ] Swagger에서 가입 → 토큰 발급 확인
    - [ ] 중복·필수 약관 미동의 에러 코드 확인
    - [ ] PR 머지
- 참고: 백엔드 기술 기획서 6.3 (Notion), 화면 WEB-JOIN-02
- 의존성: 선행 — 프로젝트 세팅 이슈
- 연관 파트
    - 영향 주는 파트: DE — 약관 항목·에러 문구 확정
    - 영향 받는 파트: FE — WEB-JOIN-02 화면 연동
    - 공유 필요 사항: 에러 코드 목록, Refresh 쿠키 방식

**작성 예시 — [LLM]**

- 제목: `[LLM] 형식 요소 판정 엔드포인트 구현`
- 목적: Spring이 사용자 프롬프트의 형식 요소(6요소) 판정을 받을 수 있도록 `POST /v1/analyze`를 구현한다
- 작업 내용
    - [ ] `ai-server/src/routers/`에 `POST /v1/analyze` 구현
    - [ ] `ai-server/src/schemas/`에 요청·응답 스키마 (`docs/dev/specs/interfaces.md` > 3.3 기준)
    - [ ] 판정 실패 시 `degraded` 응답 (`interfaces.md` > 3.9 · 3.10)
- 완료 조건
    - [ ] FastAPI `/docs`에서 정상 요청·응답 확인
    - [ ] `uv run --directory ai-server pytest -q` 통과
    - [ ] PR 머지
- 연관 파트
    - 영향 받는 파트: BE — `infra/ai` DTO 연동
    - 공유 필요 사항: 응답 스키마 (`interfaces.md` > 3.3)

## 4. 하위 작업 (Subtask)

하위 작업은 **가능하면 만들지 않는다.** 큰 작업은 에픽 아래 Story·Task로 나눈다.

- 이유: 하위 작업은 브랜치·PR·상태가 상위 이슈와 따로 움직여 추적이 어렵다. 같은 크기의 작업은 Story·Task로 두는 편이 브랜치(`KAN-번호`)와 1:1로 맞는다.
- 예외: 이미 하위 작업으로 만들어진 이슈를 고칠 때, 또는 팀이 명시적으로 하위 작업을 요청했을 때만 다룬다.
    - 상위 이슈 키를 확인하고, 그 이슈가 실제로 있는지 조회한다.
    - 본문은 3장 또는 6장 양식을 쓰고, "의존성"에 상위 이슈를 적는다 (`- 상위: KAN-00 (상위 이슈 제목)`).
    - 등록 시 필드: `issuetype: Subtask`, `parent: 상위 이슈 키`
- 한 이슈를 PR 여러 개로 나누면 작업 내용에 PR별 항목을 적는다 (예: `### PR ① …`, `### PR ② …`).

## 5. 버그 (Bug)

```markdown
<!--
[AI 작성 안내 — Jira MCP·커넥터로 등록할 때]
이슈 유형: Bug
제목 형식: [파트] 현상 한 줄
  예) [BE] JWT 토큰 만료 시간 계산 오류로 세션이 조기 종료됨
  예) [LLM] 형식 요소 판정 결과가 항상 낮은 충족률 반환
각 섹션 작성 기준:
- "심각도": 서비스 영향도로 판단한다. 아래 기준 표에서 하나만 고른다.
- "현상": 예상 결과와 실제 결과의 차이. "안 된다"는 현상 설명이 아니다.
- "재현 방법": 번호 순서로, 조건 → 동작 → 결과 흐름으로.
- "환경": 채널(익스텐션/웹), 서버(local/dev/prod), request_id.
- LLM 응답 품질 문제: 재현 프롬프트·모델명·rubric_version을 반드시 첨부한다.
- 코드·로그는 코드펜스(```)로 감싼다.
등록 시 필드:
  issuetype: Bug
  summary:   [파트] 현상 한 줄
  priority:  심각도 기준 표 참고
  labels:    [파트명]

```

## 재현 방법
1. 
2. 
3. 

## 기대 결과 / 실제 결과
- 기대: 
- 실제: 

## 환경
- 채널: 익스텐션 / 웹
- 서버: local / dev / prod
- request_id: 

## 첨부
스크린샷, 로그, 재현 프롬프트

## 연관 파트
- 원인 추정 파트: 
- 영향 받는 파트: 
```

### 심각도 기준

| 심각도 | 기준 | 예시 | Jira 우선순위 | 대응 |
| --- | --- | --- | --- | --- |
| **Critical** | 서비스 사용 불가, 데이터 손실·개인정보 노출 | 로그인 전체 불가, 타인 기록 조회됨 | Highest | 즉시. 팀 채널 공지 |
| **High** | 핵심 기능 오동작, 우회 방법 없음 | 진단 결과 레벨 저장 안 됨, Before/After 생성 실패 | High | 당일 |
| **Medium** | 기능 일부 오동작, 우회 방법 있음 | 새로고침하면 해결, 특정 입력에만 에러 | Medium | 스프린트 내 |
| **Low** | 화면·문구·사소한 불편 | 오탈자, 정렬 어긋남 | Low | 여유 있을 때 |

- 심각도와 Jira 우선순위 필드를 위 표대로 맞춘다.
- LLM 응답 품질 문제(판정 오류 등)는 재현 프롬프트·`rubric_version`·`request_id`를 반드시 첨부한다.

## 8. 상태 흐름

| 상태 | 옮기는 시점 |
| --- | --- |
| 백로그 | 이슈는 만들었지만 이번 스프린트에서 하지 않음 |
| 해야 할 일 | 본문 작성·담당자 지정 완료, 이번 스프린트에서 함 |
| 진행 중 | 작업 브랜치 생성 |
| PR 리뷰 중 | PR을 Ready for review로 전환 |
| QA 대기 | 머지 후 QA가 필요한 작업 |
| QA 중 | QA 진행 |
| QA 완료 | QA 통과 |
| 완료 | 완료 조건 전부 충족 (QA가 필요 없으면 머지 후 바로) |

- 한 이슈를 PR 여러 개로 나누면 마지막 PR이 머지된 뒤 `완료`로 바꾼다.

## 9. AI로 작성·등록할 때

- 절차는 `docs/dev/ai/prompts/20-issue-write.md`를 따른다. 초안을 먼저 보여 주고, 사람이 승인한 뒤 등록한다.

| 도구 | 연결 | 등록 |
| --- | --- | --- |
| Claude Code | `.mcp.json`의 Jira MCP (`jira_get_issue` · `jira_create_issue` · `jira_update_issue`). 설정은 `docs/dev/ai/README.md` > `5. MCP·CLI 연결 (Claude Code)` | 초안 파일(`.claude/drafts/KAN-<번호>-issue.md`) 확인 → 승인 → 등록. 체크박스가 있으면 본문 전체를 ADF로 바꿔 `format: adf`로 보낸다. 생성은 실행 전 확인 창이 뜬다 |
| claude.ai 웹 채팅 | Atlassian 커넥터 (claude.ai → Settings → Connectors → Atlassian) | 초안 코드블록 확인 → 승인 → 등록. 커넥터가 없으면 직접 붙여 넣기. 등록 후 체크박스가 `[ ]` 글자로 보이면 Jira 화면에서 체크리스트로 바꾼다 |

ADF 변환 규칙 (AI가 등록할 때)

| 마크다운 | ADF |
| --- | --- |
| `## 제목` · `### 제목` | `heading` (level 2 · 3) |
| 문장 | `paragraph` |
| `- 항목` | `bulletList` > `listItem` > `paragraph` |
| `- [ ] 항목` · `- [x] 항목` | `taskList` > `taskItem` (`state`: `TODO` · `DONE`, `localId`는 항목마다 새 UUID) |
| `` `코드` `` | `text` + `code` mark |

- 등록 후 이슈를 다시 조회해 체크리스트 항목 수가 초안과 같은지 확인한다.

```markdown
20-issue-write로 이슈 만들어줘:
  제목: [LLM] 형식 요소 판정 엔드포인트 구현
  유형: Task
  에픽: 진단
  라벨: LLM, 진단
